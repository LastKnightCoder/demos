CSS MODULE FIELD REPORT / SCROLL SNAP

Scroll Snap 深度报告

Scroll Snap 的价值不是“做一个轮播”，而是把滚动结束后的落点变成可声明、可维护、可渐进增强的布局规则。

Module: CSS Scroll Snap
Axis: x / y / both
Mode: mandatory / proximity

执行摘要

它解决什么

普通滚动可以停在任意像素位置。Scroll Snap 让浏览器在滚动结束后自动选择最近或最合适的停靠点，尤其适合卡片、分页、轮播和画廊。

它不解决什么

它不负责打开关闭状态、无限循环、复杂手势识别，也不应该用来强行劫持普通文章阅读。它是滚动落点约束，不是交互框架。

心智模型

Scroll Container

真正滚动的元素。它必须有 overflow，并通过 scroll-snap-type 声明轴向和强度。

overflow-xscroll-snap-type

Snapport

容器内部用于吸附对齐的目标窗口。默认接近可视区域，用 scroll-padding 调整。

scroll-paddingtarget window

Snap Area

子项参与吸附的区域。默认接近元素自身盒子，用 scroll-margin 调整。

scroll-marginsnap item

基础语法

最小可用结构

Scroll Snap 的职责分离非常明确：容器决定吸附规则，子项决定对齐点。如果写了 scroll-snap-align 仍然没效果，第一件事就是检查父级是不是实际滚动容器。

Minimal CSS
.scroller {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-padding-inline-start: 24px;
}

.item {
  flex: 0 0 320px;
  scroll-snap-align: start;
}

02

纵向分页 / y mandatory

当内容天然是一屏一屏时，scroll-snap-type: y mandatory 可以把连续滚动改造成稳定分页。

重点是：每一页的高度要足够稳定，否则吸附会让人觉得页面在抢控制权。普通长文章更适合 proximity 或完全不用吸附。

使用右侧按钮或在 demo 内滚动。每一屏都设置了 scroll-snap-align: start。

03

吸附强度 / mandatory vs proximity

mandatory 表示强制吸附。只要滚动结束附近存在合法 snap point，浏览器就会把位置拉回某个停靠点。

proximity 表示接近时才吸附。用户停得离 snap point 比较远时，浏览器可以尊重这个停留位置，不强行拉回。

分别滚动两个 demo 后松手。mandatory 更像分页；proximity 更像带“轻微磁吸”的普通滚动。

05

关键节点 / scroll-snap-stop

scroll-snap-stop: always 的差异只发生在“滚动操作会越过多个 snap point”的场景。慢慢拖动、滚动条拖拽、锚点跳转、很多脚本滚动都不一定触发这种 pass-over 语义。

右侧保留原生对照：上方 normal 轨道的 03 只是视觉标记；下方 always 轨道的 03 才真正设置了 scroll-snap-stop: always。如果你的设备/浏览器没有明显差异，这本身就是这个属性的一个重要学习点。

建议用触控板快速甩动或触摸屏惯性滑动观察。鼠标滚轮、按钮、scrollTo 这类输入经常看不出差别。

scroll-snap-type: both mandatory 让水平和垂直方向都参与吸附。它适合二维内容，比如图片墙、地图式面板、产品矩阵。

轮播控制 / buttons + smooth scroll

Scroll Snap 可以承担轮播的“最终落点”，按钮只负责把对应 slide 滚进视野。这样保留了原生滚动条、触控板、键盘和触摸惯性。

这里用 scrollIntoView() 触发平滑滚动，容器用 scroll-snap-align: center 保证最后居中。动效会遵守 prefers-reduced-motion。

});

生产使用准则

  • 先判断内容是否天然分段。 卡片、slide、步骤、图片墙适合；连续阅读内容通常不应该强制吸附。
  • mandatory 用在明确分页。 如果只是希望靠近章节时稍微对齐，用 proximity 会更温和。
  • 固定头部用 scroll-padding。 它描述容器的吸附目标窗口，比给内容塞空白更稳定。
  • 特殊子项用 scroll-margin。 它只调整某个 snap area，适合少数项目的额外停靠距离。
  • 按钮只是辅助导航。 保留滚动条、触控板、触摸和键盘输入，让 Scroll Snap 负责最终落点。

前后对比

手写滚动吸附

  • 监听 scroll，计算最近元素
  • 手动处理触摸、滚轮和键盘差异
  • 容易和浏览器惯性滚动互相抢控制权
  • 固定头部、响应式、边缘条件都要单独维护

CSS Scroll Snap

  • 声明轴向、强度、子项对齐点
  • 浏览器保留原生输入和滚动惯性
  • 用 scroll-padding / scroll-margin 处理偏移
  • 可渐进增强，不支持时仍是普通滚动
