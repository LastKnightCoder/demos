两种编码方式对比

对比维度 application/x-www-form-urlencoded multipart/form-data
HTML 默认 ✓ 是 ✗ 需指定 enctype
文件上传 ✗ 不支持 ✓ 支持
二进制数据 ✗ 不支持 ✓ 原样传输
中文/特殊字符 percent-encoding，体积膨胀 原样传输，无膨胀
请求体格式 k=v&k=v 单一字符串 多段结构，boundary 分隔
服务端解析 简单，内置支持 需要 multipart 解析库
适用场景 登录、搜索、简单表单 文件上传、富表单

原因分析

为什么会解析失败

fetch 发送的 body 实际上是 multipart 格式（有 boundary 分隔各字段），但 Content-Type 头被手动覆盖成了 application/x-www-form-urlencoded，且没有 boundary。


服务端按 urlencoded 规则解析，看到的是一堆 multipart 原始字节，完全无法识别，结果是空对象或乱码。


正确做法：传 FormData 时不要设置 Content-Type，让浏览器自动加上含 boundary 的 multipart 头。
