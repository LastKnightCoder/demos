Import Map 与模块加载顺序验证

问题：Import Map 不是必须在模块之前吗？

规则：Import Map 必须在使用该映射的模块之前声明。

但这并不意味着所有 Import Map 都必须在所有模块之前！
关键理解：
  • Import Map 1 可以在 Module A 之前
  • Module A 可以在 Import Map 2 之前
  • Import Map 2 可以在 Module B 之前
  • 只要每个模块使用的标识符在它之前已被定义即可

执行时间线

1. Import Map 1 注册
定义: "lib-a", "shared"
2. Module Script 1 执行
导入: import "lib-a", import "shared"
此时 "shared" 被解析为 Map 1 的定义
3. Import Map 2 注册
定义: "lib-b", "shared" (尝试覆盖)
⚠️ "shared" 已被解析，新定义被忽略
4. Module Script 2 执行
导入: import "lib-b", import "shared"
"shared" 仍然使用 Map 1 的定义！

实际代码结构

<!-- 1. Import Map 1 --> <script type="importmap"> { "imports": { "lib-a": "data:...'Library A'", "shared": "data:...'Shared from Map 1'" } } </script> <!-- 2. Module Script 1 - 使用 Map 1 的定义 --> <script type="module"> import libA from 'lib-a'; // ✅ 正常工作 import shared from 'shared'; // ✅ 解析为 Map 1 的定义 // 此时 "shared" 已被解析 </script> <!-- 3. Import Map 2 --> <script type="importmap"> { "imports": { "lib-b": "data:...'Library B'", "shared": "data:...'Shared from Map 2'" // ⚠️ 被忽略！ } } </script> <!-- 4. Module Script 2 --> <script type="module"> import libB from 'lib-b'; // ✅ 正常工作 import shared from 'shared'; // ⚠️ 仍然是 Map 1 的定义！ </script>

结论

MDN 描述���场景确实存在：
  1. Import Map 1 定义了 "shared"
  2. Module Script 1 导入了 "shared"，此时该标识符被解析
  3. Import Map 2 尝试重新定义 "shared"，但被忽略
  4. Module Script 2 导入 "shared"，得到的仍是 Map 1 的定义
总结：
"已解析的标识符" 指的是该标识符对应的模块已经被某个 import 语句触发加载。 一旦解析发生，后续 Import Map 对该标识符的定义都会被忽略， 以确保同一个标识符在整个应用中始终指向同一个模块实例。
