Import Map: scopes 与 integrity 详解

一、scopes（作用域映射）

作用：为不同的 URL 路径定义不同的模块映射。 当从特定路径导入模块时，优先使用该作用域的映射，找不到再回退到全局 imports。

语法结构

{ "imports": { "lodash": "/libs/lodash-v4.js" // 全局默认映射 }, "scopes": { "/app/legacy/": { // 作用域路径（必须以 / 结尾） "lodash": "/libs/lodash-v3.js" // 该路径下的特定映射 }, "/app/experimental/": { "lodash": "/libs/lodash-v5.js" } } }

解析规则图示

/app/legacy/module.js → import "lodash" → /libs/lodash-v3.js

/app/experimental/module.js → import "lodash" → /libs/lodash-v5.js

/app/other/module.js → import "lodash" → /libs/lodash-v4.js

使用场景

场景 说明
版本隔离 不同模块使用不同版本的依赖，避免版本冲突
微前端 每个子应用可以有独立的依赖映射
渐进升级 新代码用新版本，旧代码保持旧版本
A/B 测试 不同路径加载不同实现

完整示例

<script type="importmap"> { "imports": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js", "utils": "/shared/utils.js" }, "scopes": { "/admin/": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.15/lodash.js", "utils": "/admin/utils-admin.js" }, "/legacy/": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@3.10.1/lodash.js" } } } </script> <!-- /admin/dashboard.js 中 --> <script type="module"> // 从 /admin/ 路径导入时： import _ from 'lodash'; // → lodash@4.17.15（scopes 中的版本） import utils from 'utils'; // → /admin/utils-admin.js </script> <!-- /public/home.js 中 --> <script type="module"> // 从其他路径导入时： import _ from 'lodash'; // → lodash@4.17.21（全局 imports） import utils from 'utils'; // → /shared/utils.js </script>

二、integrity（完整性校验）

作用：为模块指定 SRI（Subresource Integrity）哈希值， 浏览器加载模块时会验证内容是否匹配，防止代码被篡改。

语法结构

{ "imports": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" }, "integrity": { "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js": "sha384-xxx..." } }
注意：integrity 的 key 必须是完整的 URL，不是模块标识符。 这是因为同一个 URL 可能被多个标识符引用。

哈希值格式

sha384-TSskRdUpYvZ4v7ivC5O11GCphs0fpSTrY5SdAEDJtK3x6I/oGiyxiTfQox3ad/xQ └─┬─┘ └────────────────────────────────┬────────────────────────────────────┘ 算法 Base64 编码的哈希值

支持的算法：sha256、sha384（推荐）、sha512

如何生成哈希值

# 方法 1：命令行 curl -s "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" | \ openssl dgst -sha384 -binary | openssl base64 -A # 方法 2：Node.js const crypto = require('crypto'); const content = await fetch(url).then(r => r.text()); const hash = crypto.createHash('sha384').update(content).digest('base64'); console.log(`sha384-${hash}`); # 方法 3：在线工具 # https://www.srihash.org/

完整示例

<script type="importmap"> { "imports": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js", "dayjs": "https://esm.sh/dayjs@1.11.10" }, "integrity": { "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js": "sha384-TSskRdUpYvZ4v7ivC5O11GCphs0fpSTrY5SdAEDJtK3x6I/oGiyxiTfQox3ad/xQ", "https://esm.sh/dayjs@1.11.10": "sha384-B1ywcSN6kXVFtoMWvs4OXd6uONqfz2dysENSrDD3+IE6EzNqHvigyf8xKkPQcB6w" } } </script>

验证失败时的行为

如果模块内容与哈希值不匹配，浏览器会：
  • 拒绝加载该模块
  • 在控制台报错：Failed to find a valid digest in the 'integrity' attribute
  • 依赖该模块的代码也会失败

使用场景

场景 说明
CDN 安全 确保从第三方 CDN 加载的代码未被篡改
防止 MITM 防止中间人攻击注入恶意代码
合规要求 某些安全标准要求验证外部资源完整性
缓存验证 确保缓存的内容与预期一致

三、综合示例：scopes + integrity

<script type="importmap"> { "imports": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js", "react": "https://esm.sh/react@18.2.0" }, "scopes": { "/legacy/": { "react": "https://esm.sh/react@17.0.2" } }, "integrity": { "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js": "sha384-TSskRdUpYvZ4v7ivC5O11GCphs0fpSTrY5SdAEDJtK3x6I/oGiyxiTfQox3ad/xQ", "https://esm.sh/react@18.2.0": "sha384-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx", "https://esm.sh/react@17.0.2": "sha384-yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy" } } </script>
最佳实践：
  • 为所有外部 CDN 资源添加 integrity
  • 使用 scopes 隔离不同版本的依赖
  • 定期更新哈希值（当依赖版本更新时）
  • 在 CI/CD 中自动生成和验证哈希值
