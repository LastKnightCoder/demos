Import Maps - 多版本依赖管理

为什么需要多版本管理？

在大型项目或微前端架构中，经常会遇到以下情况：

  • 不同团队开发的模块依赖同一个库的不同版本
  • 渐进式升级过程中，新旧代码需要共存
  • 第三方库依赖特定版本的其他库
  • 需要同时测试多个版本的兼容性

版本管理策略

策略 1：使用版本后缀

{ "imports": { "lodash@3": "https://cdn.jsdelivr.net/npm/lodash-es@3.10.1/lodash.js", "lodash@4": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js", "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" } }
// 使用特定版本 import lodash3 from 'lodash@3'; import lodash4 from 'lodash@4'; // 使用默认版本（最新） import _ from 'lodash';

策略 2：使用 Scopes 隔离

{ "imports": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" }, "scopes": { "/legacy-app/": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@3.10.1/lodash.js" }, "/new-app/": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" } } }

策略 3：命名空间隔离

{ "imports": { "vendor/lodash-legacy": "https://cdn.jsdelivr.net/npm/lodash-es@3.10.1/lodash.js", "vendor/lodash-modern": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" } }

版本冲突解决

注意：多版本共存可能导致以下问题：
  • 增加页面加载时间和内存占用
  • 某些库可能不支持多实例运行
  • 全局状态可能产生冲突

最佳实践

  1. 尽量统一版本 - 多版本应该是临时方案，最终目标是统一
  2. 使用 Scopes 隔离 - 比版本后缀更清晰，更容易管理
  3. 文档化版本依赖 - 记录每个模块使用的版本及原因
  4. 制定升级计划 - 设定时间表逐步统一版本

渐进式迁移示例

从 Moment.js 迁移到 Day.js 的过程：

阶段 1：引入新库，保持兼容

{ "imports": { "moment": "https://esm.sh/moment@2.29.4", "dayjs": "https://esm.sh/dayjs@1.11.10" } }

阶段 2：新代码使用 Day.js，旧代码继续用 Moment

{ "imports": { "date-lib": "https://esm.sh/dayjs@1.11.10" }, "scopes": { "/legacy/": { "date-lib": "https://esm.sh/moment@2.29.4" } } }

阶段 3：完全迁移到 Day.js

{ "imports": { "date-lib": "https://esm.sh/dayjs@1.11.10" } }

版本锁定与完整性校验

使用 integrity 字段确保加载的是预期版本，防止 CDN 被篡改。
{ "imports": { "lodash": "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js" }, "integrity": { "https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js": "sha384-WjLRjwVfCzXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX" } }

生成 integrity hash 的方法：

# 使用 openssl curl -s https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js | \ openssl dgst -sha384 -binary | \ openssl base64 -A # 使用 shasum curl -s https://cdn.jsdelivr.net/npm/lodash-es@4.17.21/lodash.js | \ shasum -a 384 | \ xxd -r -p | \ base64
