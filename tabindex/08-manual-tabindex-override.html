手动设置 tabIndex 的效果测试

核心结论：手动设置 tabIndex="-1" 会覆盖元素的默认聚焦行为。 即使是 <input>、<button> 等默认可聚焦元素， 设置 tabindex="-1" 后也会从 Tab 导航中移除。

规则总结表

元素类型 默认 tabIndex 手动设置 tabindex="-1" Tab 键行为
<input> 0 覆盖为 -1 ❌ 不可聚焦（被移除）
<button> 0 覆盖为 -1 ❌ 不可聚焦（被移除）
<select> 0 覆盖为 -1 ❌ 不可聚焦（被移除）
<textarea> 0 覆盖为 -1 ❌ 不可聚焦（被移除）
<a href> 0 覆盖为 -1 ❌ 不可聚焦（被移除）
<summary> -1（特殊） 显式设置 -1 ❌ 不可聚焦（被移除）
contenteditable -1（特殊） 显式设置 -1 ❌ 不可聚焦（被移除）
<div> -1 设置为 0 ✅ 可聚焦（被加入）
重要：手动设置的 tabindex 属性优先级最高， 会覆盖浏览器的默认行为和特殊规则。

使用场景

何时使用 tabindex="-1"？

  • 临时禁用 Tab 访问： 模态框打开时，将背景内容的交互元素设置为 tabindex="-1"， 防止焦点逃逸到背景。
  • 自定义焦点管理： 复杂组件（如自定义下拉菜单）中，只让容器可聚焦，内部选项设置为 tabindex="-1"， 通过方向键导航。
  • 隐藏但保留可访问性： 某些元素视觉上隐藏（如折叠的手风琴内容），但需要通过 JS 聚焦时显示。

何时使用 tabindex="0"？

  • 自定义交互组件： 用 <div> 实现的按钮、卡片、菜单项等，需要加入 Tab 顺序。
  • 恢复默认行为： 如果之前设置了 tabindex="-1"，可以用 tabindex="0" 恢复。

注意事项

  • disabled 属性优先级更高： <button disabled tabindex="0"> 仍然不可聚焦
  • 移除 tabindex 属性会恢复默认行为： element.removeAttribute('tabindex')
  • 不要滥用 tabindex="-1"： 会破坏键盘用户的体验，只在必要时使用

JavaScript 动态控制示例

// 临时禁用元素的 Tab 访问
const input = document.querySelector('input');
input.setAttribute('tabindex', '-1');

// 恢复 Tab 访问
input.setAttribute('tabindex', '0');
// 或者移除属性，恢复默认行为
input.removeAttribute('tabindex');

// 模态框打开时，禁用背景内容
const backgroundElements = document.querySelectorAll('button, a, input');
backgroundElements.forEach(el => {
  el.dataset.originalTabindex = el.getAttribute('tabindex') || '';
  el.setAttribute('tabindex', '-1');
});

// 模态框关闭时，恢复背景内容
backgroundElements.forEach(el => {
  if (el.dataset.originalTabindex) {
    el.setAttribute('tabindex', el.dataset.originalTabindex);
  } else {
    el.removeAttribute('tabindex');
  }
});
