为什么改成 tabIndex=0 会破坏现有代码？

核心问题：如果浏览器把 <summary> 和 contenteditable 的默认 tabIndex 从 -1 改成 0，会导致大量现有网站的 JavaScript 代码出现 bug。

1. 时间线：理解问题的背景

1990 年代末 - 2000 年代初
开发者开始使用 tabIndex 属性，形成了一个约定：
tabIndex === 0 表示"标准的表单控件"（button, input, select 等）
2000 年代中期
大量网站写了依赖 tabIndex === 0 判断的代码，用于：
- 焦点管理（模态框、菜单）
- 表单验证
- 键盘导航增强
- 无障碍功能
2014 年左右
HTML5 引入 <details> 和 <summary> 元素
问题：如果设置 summary.tabIndex = 0，会破坏现有代码的判断逻辑
最终决定
浏览器厂商决定：summary.tabIndex = -1，但仍可被 Tab 聚焦
这样既保持了向后兼容，又实现了新功能

2. 真实场景：会被破坏的代码示例

场景 1：模态框焦点管理

这是一个非常常见的代码模式，用于在模态框打开时禁用背景内容：

// 2010 年写的代码，当时还没有 <summary> 元素
function openModal() {
  // 找到所有"标准可聚焦元素"并禁用它们
  const focusableElements = document.querySelectorAll('*');

  focusableElements.forEach(el => {
    // 判断逻辑：tabIndex === 0 表示这是一个标准的可聚焦元素
    if (el.tabIndex === 0) {
      el.dataset.originalTabindex = '0';
      el.setAttribute('tabindex', '-1'); // 临时禁用
    }
  });

  showModal();
}

function closeModal() {
  // 恢复所有被禁用的元素
  const disabledElements = document.querySelectorAll('[data-original-tabindex]');
  disabledElements.forEach(el => {
    el.setAttribute('tabindex', el.dataset.originalTabindex);
    delete el.dataset.originalTabindex;
  });
}

✅ 当前行为（summary.tabIndex = -1）

打开模态框：
- button.tabIndex = 0 → 被禁用 ✓
- input.tabIndex = 0 → 被禁用 ✓
- summary.tabIndex = -1 → 不受影响 ✓

结果：代码正常工作，summary 不会被误禁用

❌ 如果改成 summary.tabIndex = 0

打开模态框：
- button.tabIndex = 0 → 被禁用 ✓
- input.tabIndex = 0 → 被禁用 ✓
- summary.tabIndex = 0 → 被误禁用 ✗

结果：summary 被错误地禁用了！
关闭模态框后，summary 的 tabindex 被错误地设置为 "0"

场景 2：表单验证

很多表单库会检查所有 tabIndex === 0 的元素，认为它们是表单控件：

// 表单验证库的代码（2012 年写的）
function validateForm(formElement) {
  const formControls = [];

  // 遍历表单内的所有元素
  formElement.querySelectorAll('*').forEach(el => {
    // 判断：tabIndex === 0 表示这是一个表单控件
    if (el.tabIndex === 0) {
      formControls.push(el);
    }
  });

  // 验证每个表单控件
  formControls.forEach(control => {
    if (control.hasAttribute('required') && !control.value) {
      showError(control, '此字段为必填项');
    }
  });
}

✅ 当前行为（summary.tabIndex = -1）

表单内的元素：
- input (tabIndex=0) → 被验证 ✓
- select (tabIndex=0) → 被验证 ✓
- summary (tabIndex=-1) → 被忽略 ✓

结果：只验证真正的表单控件

❌ 如果改成 summary.tabIndex = 0

表单内的元素：
- input (tabIndex=0) → 被验证 ✓
- select (tabIndex=0) → 被验证 ✓
- summary (tabIndex=0) → 被误判为表单控件 ✗

结果：代码尝试读取 summary.value（不存在）
可能导致 JavaScript 错误或错误的验证结果

场景 3：自定义键盘导航

一些网站实现了自定义的键盘导航，只处理"标准控件"：

// 自定义键盘导航（2011 年写的）
document.addEventListener('keydown', function(e) {
  if (e.key === 'ArrowDown' || e.key === 'ArrowUp') {
    // 找到所有"标准可聚焦元素"
    const focusableElements = Array.from(document.querySelectorAll('*'))
      .filter(el => el.tabIndex === 0);

    const currentIndex = focusableElements.indexOf(document.activeElement);

    if (e.key === 'ArrowDown') {
      const nextElement = focusableElements[currentIndex + 1];
      if (nextElement) nextElement.focus();
    } else {
      const prevElement = focusableElements[currentIndex - 1];
      if (prevElement) prevElement.focus();
    }
  }
});

✅ 当前行为（summary.tabIndex = -1）

方向键导航的元素：
- button, input, select 等标准控件
- summary 不在导航列表中 ✓

结果：只在标准控件之间导航，符合预期

❌ 如果改成 summary.tabIndex = 0

方向键导航的元素：
- button, input, select 等标准控件
- summary 也被包含在内 ✗

结果：方向键会意外地聚焦到 summary，
破坏了原本的导航逻辑

3. 影响范围：有多少网站会受影响？

保守估计：
  • 全球有数百万个网站使用了类似的 tabIndex === 0 判断逻辑
  • 这些代码大多写于 2000-2014 年间，当时 <summary> 还不存在
  • 如果浏览器突然改变 summary.tabIndex 的值，这些网站会立即出现 bug
  • 修复这些 bug 需要更新数百万个网站的代码，几乎不可能
代码类型 使用场景 受影响程度
模态框/对话框库 Bootstrap, jQuery UI, 自定义实现 高
表单验证库 jQuery Validate, Parsley.js 等 高
无障碍增强脚本 焦点管理、键盘导航 高
自定义组件库 下拉菜单、标签页、手风琴 中
测试工具 查找可聚焦元素进行自动化测试 中

4. 浏览器的解决方案：特殊处理

浏览器厂商采用了一个巧妙的解决方案：

双轨制：
  • JavaScript 层面：element.tabIndex 返回 -1（保持向后兼容）
  • 浏览器内部：仍然将这些元素视为可聚焦，Tab 键可以到达
这样既不破坏现有代码，又实现了新功能。 
// 现有代码的判断逻辑不会被破坏
const summary = document.querySelector('summary');

console.log(summary.tabIndex);  // -1（保持兼容）

// 但浏览器内部仍然让它可以被 Tab 聚焦
// 按 Tab 键可以到达 summary 元素

// 现有代码的判断逻辑：
if (summary.tabIndex === 0) {
  // 这个分支不会执行，所以不会误判 summary 为标准控件
  console.log('这是一个标准控件');
}

6. 总结：为什么不能改？

原因 详细说明
向后兼容性 数百万网站依赖 tabIndex === 0 判断标准控件，改变会导致大规模 bug
约定俗成 开发者社区已经形成共识：tabIndex === 0 = 标准控件
修复成本 修复所有受影响的网站几乎不可能，很多网站已经无人维护
语义价值 tabIndex = -1 提供了语义信息：这是一个特殊元素
结论：改变 summary.tabIndex 的默认值会破坏 Web 的向后兼容性， 这是浏览器厂商绝对不能做的事情。保持 tabIndex = -1 是唯一合理的选择。
