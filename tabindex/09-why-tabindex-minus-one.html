为什么特殊元素默认 tabIndex=-1？

核心问题：为什么 <summary> 和 contenteditable 的默认 tabIndex 是 -1，而不是像 <button> 那样设置为 0？

1. 设计原因：区分"原生可聚焦"和"条件可聚焦"

元素类型 默认 tabIndex 设计意图
原生可聚焦元素
<button>, <input>, <a href> 		0 这些元素天生就是交互控件，无论在什么上下文中都应该可聚焦。
tabIndex=0 明确表示"我是标准的可聚焦元素"。
条件可聚焦元素
<summary>, contenteditable 		-1 这些元素的可聚焦性依赖于上下文：
- <summary> 只在作为 <details> 的子元素时才可聚焦
- contenteditable 只在属性值为 true 时才可聚焦
tabIndex=-1 表示"我不是标准的可聚焦元素，但浏览器会根据上下文决定"。

为什么不统一设置为 0？

  • 语义清晰：tabIndex=-1 告诉开发者"这个元素的聚焦行为是特殊的，不是标准的"
  • 可扩展性：如果未来需要改变行为，tabIndex=-1 提供了更大的灵活性
  • 向后兼容：早期 HTML 规范中这些元素不可聚焦，后来才加入特殊处理

2. 实际差异：开发者可以区分元素类型

通过 tabIndex 值，开发者可以判断元素的聚焦行为类型：

// 判断元素是否是"原生可聚焦元素"
function isNativelyFocusable(element) {
  // tabIndex === 0 且未手动设置 tabindex 属性
  return element.tabIndex === 0 && !element.hasAttribute('tabindex');
}

// 判断元素是否是"特殊可聚焦元素"
function isSpeciallyFocusable(element) {
  // tabIndex === -1 但实际可聚焦
  return element.tabIndex === -1 &&
         (element.tagName === 'SUMMARY' ||
          element.contentEditable === 'true');
}

// 测试
const button = document.querySelector('button');
const summary = document.querySelector('summary');

console.log(isNativelyFocusable(button));   // true
console.log(isNativelyFocusable(summary));  // false
console.log(isSpeciallyFocusable(summary)); // true

3. 历史原因：向后兼容

历史背景：
  • <summary> 是 HTML5 新增的元素（2014 年左右）
  • contenteditable 最初是 IE 的私有特性（1990 年代末），后来才标准化
  • 这些特性加入时，已经有大量网站依赖现有的 tabIndex 行为

如果当时设置为 tabIndex=0 会发生什么？

  • 开发者可能会误以为这些元素和 <button> 完全一样
  • 某些依赖 tabIndex === 0 判断的代码会误判
  • 破坏了"tabIndex=0 表示标准可聚焦元素"的约定

4. 对比：如果它们的 tabIndex 是 0

❌ 假设 summary 的 tabIndex=0

const summary = document.querySelector('summary');
console.log(summary.tabIndex); // 0

// 开发者可能会误以为：
// "哦，tabIndex=0，那它和 button 一样"
// 但实际上它的行为是特殊的：
// - 只在 details 内部才可聚焦
// - 点击会触发 details 的展开/折叠
// - 不能用 disabled 属性禁用

容易让开发者产生误解，认为它是标准的交互控件。

✅ 实际 summary 的 tabIndex=-1

const summary = document.querySelector('summary');
console.log(summary.tabIndex); // -1

// 开发者会注意到：
// "咦，tabIndex=-1，但它可以被 Tab 聚焦？"
// "这说明它有特殊行为，我需要查文档"
//
// 这样开发者会更谨慎地处理这个元素

明确告诉开发者：这个元素的聚焦行为是特殊的。

6. 总结：为什么这样设计？

原因 说明
语义区分 tabIndex=0 表示"标准可聚焦元素"，tabIndex=-1 表示"特殊可聚焦元素"
开发者提示 tabIndex=-1 提醒开发者这个元素的行为是特殊的，需要注意
向后兼容 保持与早期规范的兼容性，不破坏现有代码
可扩展性 未来如果需要改变行为，tabIndex=-1 提供了更大的灵活性
条件可聚焦 这些元素的可聚焦性依赖于上下文，不是无条件的
结论：虽然 Tab 键行为看起来一样，但 tabIndex=-1 是一个语义标记，告诉开发者"这个元素的聚焦行为是特殊的，不是标准的交互控件"。 这是一种设计上的权衡，牺牲了一点一致性，换来了更清晰的语义和更好的向后兼容性。

7. 实际影响：开发者需要注意什么？

  • 不要只看 tabIndex 值判断可聚焦性： 需要实际测试或检查元素类型
  • 手动设置 tabindex 时要谨慎： <summary tabindex="-1"> 会真的变成不可聚焦
  • 焦点管理时要包含这些特殊元素： 在计算可聚焦元素时，不能只查询 [tabindex="0"] 
// ❌ 错误：只查询 tabindex="0" 的元素
const focusable = document.querySelectorAll('[tabindex="0"]');

// ✅ 正确：查询所有可能可聚焦的元素
const focusable = document.querySelectorAll(
  'a[href], button, input, select, textarea, ' +
  'details, summary, [contenteditable="true"], [tabindex="0"]'
);
