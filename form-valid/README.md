# CSS 表单验证伪类详解

## 概述

CSS 提供了四个用于表单验证的伪类选择器，用于根据表单元素的验证状态应用样式。

## 四个伪类对比

### 1. `:valid`

- ​**作用**: 匹配通过验证的表单元素
- ​**触发时机**: 元素值满足所有验证约束时立即触发
- ​**特点**: 从页面加载开始就会生效，即使用户未与表单交互

### 2. `:invalid`

- ​**作用**: 匹配未通过验证的表单元素
- ​**触发时机**: 元素值不满足验证约束时立即触发
- ​**特点**: 从页面加载开始就会生效，可能导致空表单显示错误样式

### 3. `:user-valid`

- ​**作用**: 匹配通过验证的表单元素（仅在用户交互后）
- ​**触发时机**: 用户与元素交互后，且值满足验证约束
- ​**特点**: 更友好的用户体验，避免页面加载时显示验证状态

### 4. `:user-invalid`

- ​**作用**: 匹配未通过验证的表单元素（仅在用户交互后）
- ​**触发时机**: 用户与元素交互后，且值不满足验证约束
- ​**特点**: 只在用户操作后显示错误，避免干扰初始状态

## 关键区别

| 特性 | `:valid` / `:invalid` | `:user-valid` / `:user-invalid` |
| --- | --- | --- |
| 触发时机 | 立即（页面加载时） | 用户交互后 |
| 用户体验 | 可能过早显示错误 | 更友好，避免初始错误提示 |
| 浏览器支持 | 广泛支持 | 较新特性，需检查兼容性 |
| 适用场景 | 实时验证反馈 | 渐进式验证反馈 |

## 浏览器兼容性

- `:valid` 和 `:invalid`: 所有现代浏览器支持
- `:user-valid` 和 `:user-invalid`: Chrome 119+, Edge 119+, Safari 16.5+, Firefox 88+

## 最佳实践

1. ​**优先使用 **​**`:user-invalid`**: 避免在用户输入前显示错误信息
2. ​**提供清晰的视觉反馈**: 使用颜色、图标和提示文本
3. ​**考虑可访问性**: 不要仅依赖颜色，添加文本说明
4. ​**渐进增强**: 为不支持新伪类的浏览器提供降级方案
