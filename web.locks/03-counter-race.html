Demo 03

竞态条件：有锁 vs 无锁

10 个并发工作者同时对同一个计数器执行"读取 → 加一 → 写入"。 观察无锁版本如何产生数据丢失，以及有锁版本如何保证结果正确。

代码对比
❌ 无锁（有竞态风险）
async function increment() {
  // 读取当前值
  const val = await readCounter();
  // ⚠️ 此时其他工作者
  // 也可能读到同一个值！
  await sleep(10);
  // 写入（可能覆盖他人）
  await writeCounter(val + 1);
}
✅ 有锁（原子操作）
async function increment() {
  await navigator.locks.request(
    'counter', async () => {
      const val = await readCounter();
      // 独占持有，无竞争
      await sleep(10);
      await writeCounter(val + 1);
    });
}

💡 竞态条件发生在"读取-修改-写入"之间存在异步间隙时。多个工作者读到同一个旧值， 各自加一后写回，导致多次递增只产生一次效果。Web Locks 通过串行化这个操作序列来消除竞态。
