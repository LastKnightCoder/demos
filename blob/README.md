## Blob 是什么

`Blob` 是 **Binary Large Object** 的缩写，在浏览器里表示一段不可变的原始数据。它不关心这段数据来自哪里，可以来自字符串、二进制数组、Canvas、网络响应、本地文件切片，甚至另一个 Blob。

可以把 Blob 理解成“浏览器内存中的文件内容”，但要注意：

- Blob 本身没有文件名、路径、最后修改时间。
- Blob 只描述数据内容、字节大小和 MIME type。
- Blob 内容创建后不可变；修改内容的方式是创建新的 Blob。
- `File` 是 Blob 的子类，额外增加了 `name`、`lastModified` 等文件元信息。
- Blob 不能直接显示在页面上，通常要先读取、转换为对象 URL，或传给支持 Blob 的 API。

## 核心语法

### 创建 Blob

```js
const blob = new Blob(blobParts, options);
```

完整形态：

```js
const blob = new Blob(
  [
    'hello\n',
    new Uint8Array([65, 66, 67]),
    new Blob(['nested blob'], { type: 'text/plain' })
  ],
  {
    type: 'text/plain;charset=utf-8',
    endings: 'transparent'
  }
);
```

### `blobParts`

`blobParts` 是一个可迭代对象，常见写法是数组。数组里的每一项可以是：

- 字符串：会按 UTF-8 编码写入 Blob。
- `ArrayBuffer`：原始二进制缓冲区。
- `TypedArray`：如 `Uint8Array`、`Int16Array`、`Float32Array`。
- `DataView`：对 ArrayBuffer 的视图。
- `Blob`：可以把多个 Blob 拼接成新 Blob。

示例：

```js
const textPart = 'name,score\n';
const bytesPart = new Uint8Array([49, 44, 57, 56, 10]); // "1,98\n"
const footerPart = new Blob(['# generated by browser\n']);

const csvBlob = new Blob([textPart, bytesPart, footerPart], {
  type: 'text/csv;charset=utf-8'
});
```

### `options.type`

`type` 是 Blob 的 MIME type，例如：

```js
new Blob(['hello'], { type: 'text/plain;charset=utf-8' });
new Blob([JSON.stringify(data)], { type: 'application/json' });
new Blob([svgText], { type: 'image/svg+xml' });
new Blob([htmlText], { type: 'text/html' });
```

注意：

- `type` 不会验证内容是否真的符合该 MIME type。
- `type` 主要用于告诉后续 API 如何解释这段数据，例如下载文件、预览图片、上传请求头。
- 没传 `type` 时，`blob.type` 是空字符串。

### `options.endings`

`endings` 只影响字符串部分的换行符处理：

```js
new Blob(['a\nb'], { endings: 'transparent' });
new Blob(['a\nb'], { endings: 'native' });
```

取值：

- `transparent`：默认值，保持字符串里的换行符不变。
- `native`：把字符串里的 `\n` 转换成当前系统的原生换行符。

工程里通常使用默认的 `transparent`，因为网络协议、CSV、JSON、日志等格式一般希望换行稳定可控。

## 属性与方法

### `blob.size`

返回 Blob 的字节数，不是字符数。

```js
const blob = new Blob(['你好']);
console.log(blob.size); // 6，UTF-8 中每个中文通常占 3 字节
```

### `blob.type`

返回 Blob 创建时设置的 MIME type。没有设置时为空字符串。

```js
const blob = new Blob(['{}'], { type: 'application/json' });
console.log(blob.type); // "application/json"
```

### `blob.text()`

把 Blob 解码成字符串，返回 `Promise<string>`。

```js
const text = await blob.text();
```

适合：

- 文本文件预览。
- JSON、CSV、日志、Markdown 等小到中等文本内容。

不适合：

- 很大的文件，因为会把完整内容读入内存并解码成字符串。
- 非文本二进制内容，例如图片、音频、压缩包。

### `blob.arrayBuffer()`

把 Blob 读取为 `ArrayBuffer`，返回 `Promise<ArrayBuffer>`。

```js
const buffer = await blob.arrayBuffer();
const bytes = new Uint8Array(buffer);
```

适合：

- 解析二进制协议。
- 计算 hash。
- 传给 WebAssembly、Web Crypto、音视频解码等需要字节缓冲区的 API。

### `blob.bytes()`

把 Blob 读取为 `Uint8Array`，返回 `Promise<Uint8Array>`。

```js
if ('bytes' in Blob.prototype) {
  const bytes = await blob.bytes();
} else {
  const bytes = new Uint8Array(await blob.arrayBuffer());
}
```

`bytes()` 比 `arrayBuffer()` 少一步手动包装，但它比 `text()`、`arrayBuffer()` 更新。写面向生产环境的代码时，建议保留兼容写法。

### `blob.stream()`

返回一个 `ReadableStream`，可以分块读取 Blob。

```js
const reader = blob.stream().getReader();
let total = 0;

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  total += value.byteLength;
}
```

适合：

- 大文件读取。
- 边读边处理，不想一次性占用大量内存。
- 配合 Streams API、Compression Streams、TransformStream 等管线处理。

### `blob.slice(start, end, contentType)`

返回一个新的 Blob，内容是原 Blob 的一部分。

```js
const firstKb = blob.slice(0, 1024);
const tail = blob.slice(-1024);
const renamedType = blob.slice(0, blob.size, 'text/plain');
```

参数：

- `start`：起始字节偏移，包含该位置。负数表示从末尾倒数。
- `end`：结束字节偏移，不包含该位置。省略时到结尾。负数表示从末尾倒数。
- `contentType`：新 Blob 的 MIME type，默认是空字符串。

典型用途：

- 大文件分片上传。
- 读取文件头部判断格式。
- 只预览文件前几 KB。
- 从文件末尾读取索引、签名或尾部日志。

## Blob、File、ArrayBuffer、TypedArray、FormData、URL 的关系

### Blob vs File

`File` 是 `Blob` 的子类。

```js
input.addEventListener('change', () => {
  const file = input.files[0];

  console.log(file instanceof Blob); // true
  console.log(file instanceof File); // true
  console.log(file.name);
  console.log(file.lastModified);
});
```

共同点：

- 都有 `size`、`type`。
- 都支持 `text()`、`arrayBuffer()`、`bytes()`、`stream()`、`slice()`。
- 都可以传给 `URL.createObjectURL()`、`FormData.append()`、`fetch()` 等 API。

区别：

- Blob 是通用数据块，没有文件名。
- File 通常来自用户选择、拖拽或 File System Access API，带有文件名和修改时间。

### Blob vs ArrayBuffer

`ArrayBuffer` 是一块可被 TypedArray 读写的二进制内存。

```js
const buffer = await blob.arrayBuffer();
const bytes = new Uint8Array(buffer);
bytes[0] = 255;
```

区别：

- Blob 是不可变的数据容器，更像文件内容。
- ArrayBuffer 是可被视图读写的内存块，更适合二进制解析和计算。
- Blob 适合传输、下载、预览、切片；ArrayBuffer 适合字节级处理。

### Blob vs TypedArray

TypedArray 是 ArrayBuffer 上的类型化视图，例如 `Uint8Array`。

```js
const bytes = new Uint8Array([0x48, 0x69]);
const blob = new Blob([bytes], { type: 'application/octet-stream' });
```

TypedArray 常作为 Blob 的输入，也常作为 `arrayBuffer()` 或 `bytes()` 的输出处理方式。

### Blob vs FormData

FormData 用于构造 `multipart/form-data` 请求体，Blob 可以作为其中的字段值。

```js
const formData = new FormData();
formData.append('avatar', imageBlob, 'avatar.png');
formData.append('profile', new Blob([JSON.stringify(profile)], {
  type: 'application/json'
}), 'profile.json');

await fetch('/upload', {
  method: 'POST',
  body: formData
});
```

注意第三个参数可以给 Blob 设置上传时的文件名：

```js
formData.append('file', blob, 'report.csv');
```

### Blob vs Object URL

Blob 是数据。对象 URL 是浏览器给 Blob 创建的临时地址。

```js
const url = URL.createObjectURL(blob);
image.src = url;

URL.revokeObjectURL(url);
```

对象 URL 常用于把 Blob 交给只能接收 URL 的 DOM API，例如：

- `<img src>`
- `<video src>`
- `<audio src>`
- `<iframe src>`
- `<a href download>`
- `new Worker(url)`

## 常见使用场景

### 1. 前端生成文件并下载

```js
const csv = 'id,name\n1,Ada\n2,Linus\n';
const blob = new Blob([csv], { type: 'text/csv;charset=utf-8' });
const url = URL.createObjectURL(blob);

const a = document.createElement('a');
a.href = url;
a.download = 'users.csv';
a.click();

URL.revokeObjectURL(url);
```

适合：

- 导出 CSV、JSON、Markdown、日志。
- 把客户端计算结果保存为文件。
- 离线工具、管理后台、报表页面。

### 2. 本地文件预览

```js
const file = fileInput.files[0];
const url = URL.createObjectURL(file);
image.src = url;
```

适合：

- 上传前预览图片。
- 视频/音频本地预览。
- 文本文件读取与检查。

### 3. 文件分片上传

```js
const chunkSize = 1024 * 1024 * 5;
let offset = 0;

while (offset < file.size) {
  const chunk = file.slice(offset, offset + chunkSize);
  await uploadChunk(chunk, offset);
  offset += chunkSize;
}
```

适合：

- 大文件上传。
- 断点续传。
- 并发上传。
- 上传前计算每个分片的校验值。

### 4. Canvas、截图、图表导出

```js
const blob = await new Promise((resolve) => {
  canvas.toBlob(resolve, 'image/png');
});

const url = URL.createObjectURL(blob);
preview.src = url;
```

适合：

- 图片编辑器。
- 图表导出。
- 二维码导出。
- 截图工具。

### 5. Fetch 响应读取为 Blob

```js
const response = await fetch('/photo.jpg');
const imageBlob = await response.blob();
const url = URL.createObjectURL(imageBlob);
image.src = url;
```

适合：

- 下载远程资源后本地预览。
- 拦截响应并转换为文件。
- 离线缓存或二次处理网络资源。

### 6. 上传 Blob

```js
await fetch('/api/upload-raw', {
  method: 'POST',
  headers: {
    'Content-Type': blob.type || 'application/octet-stream'
  },
  body: blob
});
```

或通过 FormData 上传：

```js
const formData = new FormData();
formData.append('file', blob, 'data.json');

await fetch('/api/upload-form', {
  method: 'POST',
  body: formData
});
```

### 7. 运行时创建 Worker

```js
const code = `
  self.onmessage = (event) => {
    self.postMessage(event.data * 2);
  };
`;

const blob = new Blob([code], { type: 'text/javascript' });
const url = URL.createObjectURL(blob);
const worker = new Worker(url);
```

适合：

- 教学演示。
- 小型内联 Worker。
- 在无需单独构建文件的场景中动态生成脚本。

生产环境要谨慎使用，因为动态脚本不如独立 Worker 文件容易缓存、调试、审计，也可能受 CSP 限制。

### 8. 数据格式转换

```js
const jsonBlob = new Blob([JSON.stringify(data)], {
  type: 'application/json'
});

const text = await jsonBlob.text();
const parsed = JSON.parse(text);
```

也可以在 Blob、ArrayBuffer、TypedArray、ReadableStream 之间转换，用于加密、压缩、解析、预览等流程。

## 注意事项与坑点

### 1. Blob 是不可变的

下面的写法不会修改原 Blob：

```js
const blob = new Blob(['hello']);
const another = new Blob([blob, ' world']);
```

`another` 是新的 Blob，`blob` 仍然是原来的内容。

### 2. `size` 是字节数，不是字符数

```js
new Blob(['abc']).size; // 3
new Blob(['你好']).size; // 6
```

中文、emoji、特殊符号在 UTF-8 中通常占多个字节。处理分片时一定按字节理解偏移。

### 3. MIME type 不等于内容验证

```js
const blob = new Blob(['not an image'], { type: 'image/png' });
```

这段代码可以创建成功，但内容并不会神奇地变成 PNG。服务端仍需要验证文件内容，不能只信任 `blob.type` 或 `file.type`。

### 4. 对象 URL 要释放

```js
const url = URL.createObjectURL(blob);
image.src = url;

image.addEventListener('load', () => {
  URL.revokeObjectURL(url);
}, { once: true });
```

不释放对象 URL 可能造成内存占用持续增长，尤其是图片预览、视频预览、频繁导出文件的页面。

注意不要过早释放。如果元素还没完成加载就释放 URL，预览可能失败。常见做法：

- 图片：在 `img.onload` 后释放，或者页面切换时统一释放。
- 下载：点击后延迟释放，或下一次创建新 URL 前释放旧 URL。
- Worker：创建后可以在合适时机释放 URL，但仍要保留 Worker 实例并在不需要时 `terminate()`。

### 5. 大 Blob 不要随便 `text()` 或 `arrayBuffer()`

`blob.text()` 和 `blob.arrayBuffer()` 都会读取完整内容。大文件会带来：

- 内存占用高。
- 主线程压力。
- 字符串解码开销大。
- 页面响应变慢。

优先考虑：

- `blob.stream()` 分块读取。
- `blob.slice()` 只读取必要片段。
- Web Worker 中处理重任务。

### 6. `slice()` 的 `end` 不包含结束位置

```js
const blob = new Blob(['abcdef']);
await blob.slice(0, 3).text(); // "abc"
```

`slice(start, end)` 与数组切片类似，包含 `start`，不包含 `end`。

### 7. Blob 没有文件名

下载或上传时如果需要文件名，要在对应 API 上提供：

```js
anchor.download = 'report.csv';
formData.append('file', blob, 'report.csv');
```

### 8. 直接打开 HTML 文件时的安全限制

本目录里的示例都尽量设计成可直接打开，但真实项目中会遇到浏览器安全限制：

- `fetch()` 读取某些本地文件可能受限。
- Worker、模块、跨源资源可能受 CSP 或同源策略影响。
- 生产调试时建议通过本地 HTTP 服务访问，例如 `python3 -m http.server`。

### 9. Object URL 与 Data URL 不同

Blob URL：

```js
const url = URL.createObjectURL(blob); // blob:https://example.com/...
```

Data URL：

```js
const url = 'data:text/plain;base64,...';
```

主要区别：

| 对比项 | Blob URL | Data URL |
| --- | --- | --- |
| 数据位置 | 浏览器内部引用 Blob | 数据直接编码进 URL |
| 大文件 | 更合适 | URL 很长，开销更大 |
| 生命周期 | 需要 `revokeObjectURL()` | 跟字符串生命周期一致 |
| 可读性 | 不包含明文数据 | 可能暴露内容 |

### 10. 安全边界

使用 Blob 处理用户文件时，要记住：

- 前端校验只提升体验，不能替代服务端校验。
- 不要执行不可信文本生成的脚本。
- 如果把用户输入拼进 HTML/SVG Blob，仍要考虑 XSS。
- 下载文件名要避免混淆用户，例如伪装扩展名。
- CSP 可能限制 `blob:` 脚本、图片或 Worker，需要在策略中显式允许。

## 兼容性与降级

Blob 的核心能力已经非常稳定：

- `new Blob()`
- `size`
- `type`
- `slice()`
- `text()`
- `arrayBuffer()`
- `stream()`
- `URL.createObjectURL()`
- `URL.revokeObjectURL()`

需要额外注意：

- `blob.bytes()` 是较新的便捷方法，生产代码建议检测后再使用。
- `canvas.toBlob()` 是异步回调风格，可以用 Promise 包装。
- 对象 URL 在 Service Worker 中不可用；普通 Window 和 Dedicated Worker 场景更常见。
- 老旧浏览器可能需要 `FileReader` 作为降级读取方式。

FileReader 降级示例：

```js
function readBlobAsText(blob) {
  if ('text' in Blob.prototype) {
    return blob.text();
  }

  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = () => resolve(reader.result);
    reader.onerror = () => reject(reader.error);
    reader.readAsText(blob);
  });
}
```

## 速查表

| 目标 | 推荐 API |
| --- | --- |
| 创建文本文件 | `new Blob([text], { type: 'text/plain;charset=utf-8' })` |
| 创建 JSON 文件 | `new Blob([JSON.stringify(data)], { type: 'application/json' })` |
| 读取文本 | `await blob.text()` |
| 读取二进制 | `await blob.arrayBuffer()` 或 `await blob.bytes()` |
| 分块读取 | `blob.stream()` |
| 截取片段 | `blob.slice(start, end)` |
| 图片/视频预览 | `URL.createObjectURL(blob)` |
| 下载文件 | `<a href="blobURL" download="name.ext">` |
| 上传文件 | `fetch(url, { method: 'POST', body: blob })` |
| 表单上传 | `formData.append('file', blob, 'name.ext')` |
| Canvas 导出 | `canvas.toBlob(callback, type, quality)` |
| 释放临时 URL | `URL.revokeObjectURL(url)` |
